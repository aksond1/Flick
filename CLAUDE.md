# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Flick is a region screenshot and screen recording tool for Hyprland (Wayland), written in Rust with GTK4. X11 and xdg-desktop-portal are out of scope for now, but capture sits behind a trait so they can be added.

Flow: `flick` freezes the screen and the user drags a region. Then, depending on the launch's behavior, Flick copies and/or saves and closes, or shows the toolbar (Settings, Lock, Play, Edit, Copy, Download, Close).

## Status

Work follows staged milestones:

- **0-3 (done):** capture, frozen overlay, selection, Copy, Download, Lock, Esc; recording with system audio (stop by the button or by launching `flick` again) and an in-region preview; an in-region editor (brush, text, undo, redo, clear).
- **4 (done):** the settings window, launch behaviors (main, alternative), Quit behavior, Hyprland keybindings, microphone, optional guide lines, moving a locked region.
- **5:** pausing recordings, copying a recording without saving, multi-monitor (done), fractional scaling (lock checks the logical size; tested at 1.25), PKGBUILD (done, `packaging/arch`); 60 FPS under load (done: measured in the nested Hyprland on a 1920x1080 headless output showing `mpv av://lavfi:testsrc2=rate=60`, 10 s per size; idle 99 % new frames at every size, with all 12 cores busy 99.5 % at 320x240, 98.5 % at 720p, 96 % at 1080p, where the compositor itself delivers 58.7 frames/s; x264 `veryfast` keeps up, so the preset stays). Stage 5 is complete.

The spec for the settings is the user's note `~/repos/Obsidian/Flick/Settings.md`. Hardware encoding is intentionally excluded. GIF/WebM export was dropped: videos are MP4 only.

User decisions: no fastshots (removed: with a lock, a behavior that does not show the toolbar already shoots at once), no separate windows except the settings (preview and editor were moved into the region), blue accent `#1a73e8`, no resizing while recording, no "full window size" view (it belonged to an old separate-window design), no notifications (dropped for good), no pause hotkey (rejected; pausing is the toolbar button only), regions never span two monitors. License: GPL-3.0-or-later. Commits go to stage branches (`stage-N`).

## Commands

```sh
cargo build --release
cargo run                                   # open the overlay (main behavior)
cargo run -- --alt                          # alternative behavior
cargo run -- settings
cargo run -- outputs                        # headless: list outputs
cargo run -- shot --region 0,0,400,300 --file a.png   # without --file: clipboard
cargo run -- record --region 0,0,400,300 --seconds 5 --file a.mp4
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo test --lib geometry                   # one module
cargo test --test record encoder_failure    # one integration test
```

System dependencies: `gtk4`, `gtk4-layer-shell`, `ffmpeg` (with `ffprobe` for tests), `wl-clipboard`, `pipewire-pulse`; `gst-plugin-gtk4` (preview playback). Integration tests run real ffmpeg with a fake capture backend, so they need no display or audio.

## Architecture

- **Multiple monitors.** `app::open` takes a frame of every output, then opens one `Overlay` per output; they share an `overlay::Group`. A selection starting on one (`Overlay::take_selection`) clears the others' regions and is refused while another output's region is locked or being edited. The keyboard follows the pointer (`take_keyboard` on `enter`: Exclusive here, OnDemand elsewhere). Closing one closes the others still selecting (`Group::close_others`, guarded by `closing`), and so does starting a recording, since their frozen pictures would hide the live screen. Esc on an output without a region runs the quit behavior of the one with it. Dialogs and the settings hide the whole group (`Group::set_visible`). `app.rs` keeps a `Weak<Group>`.
- **Two Wayland connections.** GTK owns one; `capture/wlr.rs` (`wlr-screencopy` v3) opens its own so it can run on a separate thread. `app.rs` must grab the frame *before* the overlay is mapped, or the overlay ends up in the picture.
- **Coordinates.** Regions are logical pixels relative to one output. Conversion to frame pixels goes through `Rect::scaled`, which rounds edges rather than sizes. `Frame` is always tightly packed BGRX; stride, y-inversion and channel order are normalized in `wlr.rs`, which reads the shm buffer through a persistent `mmap` so each frame is copied only once.
- **Capture loop.** A busy Wayland socket (`WouldBlock`) is not an error, and events carry a frame id so those of a cancelled capture are ignored; both once ended recordings. Streaming is paced by `CaptureRequest::interval` to spare the compositor.
- **Recording pipeline.** The capture thread puts frames into `FrameSlot` using `copy_with_damage`, so a static screen produces nothing. `FrameSlot` keeps the newest 4 frames, numbered. `pacer.rs` turns them into constant frame rate on a monotonic clock, writing to ffmpeg's stdin: each tick takes the oldest frame not yet written (`FrameSlot::next`, at most `BACKLOG` = 2 waiting, older ones skipped), and repeats the last one only when nothing is new. Taking simply the newest frame lost every frame the compositor delivered late together with the next one (a repeat plus a skip): 98 % new frames idle and 89 % under load became 99 % and 96 %. Choosing frames by arrival time did not help. `flick record` prints the counters (`Recorder::stats`: captured, written, repeated, worst pacer lag). ffmpeg captures audio itself: system audio `@DEFAULT_MONITOR@` and the microphone `@DEFAULT_SOURCE@`, both `-f pulse` inputs that must precede the video input; with both, `amix` (`normalize=0`) mixes them. ffmpeg 9.1 rejects `-thread_queue_size` before an input. ffmpeg's stdin pipe is grown to 1 MiB so a frame takes fewer writes.
- **Pausing.** Since ffmpeg reads the audio itself, a pause ends the current ffmpeg run (a segment, `<name>.partN.mp4`, finished on a background thread) and resuming starts a new one; the capture keeps running. `Recorder::stop` joins the segments with the concat demuxer (`-c copy`), or renames a single one. Every segment uses the first frame's size. The toolbar timer leaves the pauses out (`Clock` in `overlay.rs`).
- **Stopping a recording.** The pacer drops stdin (EOF, `-shortest`), then `Encoder::finish` escalates to SIGINT and SIGKILL on timeout. Never join the pacer unconditionally: it may be blocked writing to a hung ffmpeg.
- **UI.** `ui/selection.rs` holds the selection rules with no GTK so they can be unit-tested; `ui/overlay.rs` is the layer-shell window. Closures hold `Weak` references; `Overlay` keeps itself alive through its `keep` field until closed and owns the `Preview`. The toolbar must stay strictly outside the region (`place_panel`) so it is not recorded; when nothing fits, it goes inside for screenshots and must be hidden while recording.
- **Recording overlay.** The same window turns see-through (`Overlay::set_live`): frozen picture removed, no keyboard, input region limited to the panel and reapplied on every surface `layout`. Recording starts after `UNFREEZE` so the frozen frame is not captured.
- **Moving while recording.** The panel grip moves the region (its inside must be click-through). The border follows the pointer exactly, but the screen shows it some frames late, so during a drag (`Live::Track`) the capture takes a wider window, finds the border in the picture among the positions recently drawn (`capture/track.rs`) and cuts out its inside; frames without a match are dropped. The overlay must therefore draw the border with the constants from `track.rs`. A lagging border felt jerky and pausing the video lost the movement; both were tried. The panel turns transparent meanwhile to avoid per-frame relayout. The input region opens to the whole surface for the move (`Overlay::begin_move`): since the Hyprland/GTK update of 2026-11-26, motion outside the input region stops reaching a held button, which ended the drag after its first step. Resizing while recording was deliberately removed. `record/fit.rs` absorbs one-pixel size changes caused by fractional scaling.
- **Wheel zoom.** Scrolling over the canvas while selecting scales the region around its center with its proportions (`selection::zoomed`, 1.1 per notch, limited by `MIN_SIZE` and the output). `Overlay::zoom` keeps the region from before the scrolling and the factor so far, so rounding never drifts the proportions; `ZOOM_DONE` after the last event it ends, hides the size label and runs `selected()` like the end of a drag. Not for a locked region or in the editor.
- **Reentrancy.** Hiding a widget can synchronously end a gesture, so never hold a `RefCell` borrow that a gesture handler needs while changing widgets.
- **Preview.** After stopping, the overlay plays the recording inside the region (`ui/preview.rs`); clicks are accepted only in the region and the panel, the rest of the screen stays usable. Ask questions inline: dialogs would open underneath the overlay. Recordings live in `~/.cache/flick` until the preview closes. Copy does not save: the clipboard holds a file URI that must outlive the temporary file, so it points to the saved file if there is one, otherwise to a copy in `~/.cache/flick/clipboard`, which holds only the latest one. Saving and that copy use `save::link_or_copy`: a hard link of the temporary file, a real copy only across file systems. Launching `flick` during a preview opens a new overlay.
- **Editor.** Edits in place: `ui/editor/document.rs` holds operations in frame pixels and one cairo function draws both screen and export. Annotations belong to the frozen frame, stay after leaving the editor and are included by Copy and Download. Only popovers work on the overlay (dialogs open underneath), hence the own color picker and font list. Brush and text have separate colors. Escape or a press elsewhere finishes the text being typed, never discards it; undo takes it back. Undo and redo use hardware key codes so they work in any keyboard layout. The text being typed is a `TextView` sized by hand to match the pango rendering. `Stepper` replaces `SpinButton`, whose layout cannot be made compact, and both tools use equally wide controls so the panel keeps its size. Popover key events do not reach the window's key controller.
- **Launches and behaviors.** `config::Launch` is how Flick was started; GUI launches go through `GApplication` command lines (`HANDLES_COMMAND_LINE`) as plain words (`main`, `alt`, …), kept away from GApplication's own option parsing, so the running instance learns what a second launch wants. `Config::behavior` gives copy/save/open for a launch. A behavior without `open` acts on mouse release (`Overlay::selected`) and closes; with a valid lock it acts in `app::shoot` without any overlay. With `open`, the copy/save runs after each completed selection and again on leaving the editor. Once an overlay has saved a file (`saved`), every later delivery rewrites that file instead of making a new one. `Config::problem` holds the rules (behaviors differ, one shows the toolbar, keys differ); the settings window saves only valid settings.
- **Quit.** Esc and the toolbar's Close run `config.quit` on the way out (`Overlay::quit`, `Preview::request_close`).
- **Save dialogs.** "Always ask where to save" uses `ui::ask_path` (`gtk::FileDialog`). For screenshots it applies only to the Download button (saving after selecting or on Quit uses the folder), recordings ask on every save. Dialogs open underneath the overlay, so the overlay window is hidden meanwhile and shown again unless it closes. The same goes for the settings window (`Overlay::open_settings`), after which the overlay reloads the config.
- **Settings window** (`ui/settings.rs`) is one per process (`CURRENT`), keeps itself alive through `keep` like the overlay, and saves every valid change at once. Reset to Defaults (confirmed inline) saves `Config::default()` and rebuilds the page (`Settings::rebuild`); widgets the struct keeps across builds (key buttons, Hyprland status, the file name example) are removed from their old rows first. Typing a keybinding inhibits the compositor's shortcuts (`Toplevel::inhibit_system_shortcuts`) so bound keys reach the window, and translates the keycode without modifiers (Alt+Print is `Sys_Req` otherwise); launches are ignored meanwhile (`settings::is_capturing`).
- **Hyprland keybindings** (`hypr.rs`): Flick writes `flick.lua` (or `flick.conf` when there is no `hyprland.lua`) next to the user's config, with `description = "flick"` (`bindd` in `.conf`) so `hyprctl binds` tells its own bindings apart for the conflict warning; in Lua mode the bind's `arg` is an opaque id. Adding the `require("flick")` line happens only on the user's click. Every valid save, and opening the window, rewrites the file when it differs from the settings: keys can become valid through any change, not only a key change, and a stale file swapped Print and Alt+Print once. Changes reload Hyprland with `hyprctl reload config-only`.
- **Styling** is one CSS string in `ui/overlay.rs`, scoped under `.flick-toolbar`; the settings window has its own, scoped under `.flick-settings`, on top of the system theme.
- **Clipboard** goes through `wl-copy`, whose forked process keeps the content alive after Flick exits.
- **Lock** (`~/.local/state/flick/lock.toml`) is valid only if the whole `OutputInfo` still matches: name, size, scale and logical size. The logical size comes from `xdg-output` in `wlr.rs`, because `wl_output` reports scale 2 for every fractional scale above 1; lock files without it never match. A locked region cannot be resized or redrawn, but it can be moved (inside drag or the recording grip); `Overlay::keep_lock` saves the new place. Config is `~/.config/flick/config.toml`.
- **Single instance** comes from the `GtkApplication` D-Bus id `dev.flick.Flick`.

## Testing the UI

Do not inject input into the user's live session. Run a nested `Hyprland -c <config>` with `HYPRLAND_NO_SD_VARS=1 HYPRLAND_NO_SD_NOTIFY=1` on a private bus (`dbus-daemon --session --address=unix:path=$RT/bus --fork`, its address in `DBUS_SESSION_BUS_ADDRESS` for both Hyprland and Flick), and run Flick there with `GTK_A11Y=none GDK_DEBUG=no-portals` and private `XDG_CONFIG_HOME`, `XDG_STATE_HOME` and `XDG_CACHE_HOME`. Also use a private `XDG_RUNTIME_DIR` (a short path, e.g. `mktemp -d /run/user/$UID/fk.XXXXXX`, because socket paths are limited to about 108 bytes) and pass the host socket as an absolute path in `WAYLAND_DISPLAY`: a private D-Bus alone let the accessibility service overwrite the real session's `at-spi` socket.

The nested window is tiled by the host, so its output size and scale vary. Wait about 12 s after start, read the size from `flick outputs` and pass it as `VPTR_SIZE`; pointer coordinates are then physical pixels. For a second monitor run `hyprctl output create headless` (it becomes `HEADLESS-1`) and give it an `hl.monitor` rule with a position beside the first, then `hyprctl reload`; with several outputs `VPTR_SIZE` is the logical size of the whole layout and coordinates are global logical ones. A fractional `scale` in that rule tests fractional scaling (Hyprland replaces invalid scales, e.g. 1.5 at 800x600 becomes 1.6). `grim -o NAME` screenshots one output.

Programs that the nested Hyprland starts (its keybindings run `flick`) get Hyprland's environment, not yours, so put `hl.env("GDK_DEBUG", "no-portals")`, the private `XDG_*` directories and `DBUS_SESSION_BUS_ADDRESS` of a private `dbus-daemon` into the nested config. Otherwise GTK's file dialog goes through `xdg-desktop-portal` on the nested bus, and that portal inherited the host's `WAYLAND_DISPLAY`: the dialog opened in the user's real session. Kill only processes whose environment has the private `XDG_RUNTIME_DIR`; `pkill -f flick` also matches your own shell.

Set `audio = false` in the test config unless you set up audio as below; ffmpeg fails without a PulseAudio server. For audio, run private `pipewire`, `wireplumber -p policy` and `pipewire-pulse` in that runtime directory with a `module-null-sink` as the default sink, so the user's audio is never touched.

`examples/vptr.rs` (virtual mouse; steps as arguments, `w N`/`W N` scroll the wheel down/up) and `examples/vesc.rs` (keyboard; takes a file from `xkbcli compile-keymap` and evdev codes with `c`/`a`/`s` prefixes for Ctrl/Alt/Shift, e.g. `a99` is Alt+Print; Escape by default) drive it. Hyprland 0.57 parses its config as Lua, so `.conf` syntax such as `monitor=` fails. Wait a second or so after a click before taking a screenshot, since the UI may not have redrawn.
